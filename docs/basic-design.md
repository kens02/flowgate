# 基本設計書

## 1. システム概要
本システム(flowgate)は、従業員が休暇を申請し、事前に設定されたルートに従って上長が承認・決裁を行うための一連のワークフローを電子化するシステムである。PoC（概念実証）として休暇申請機能に絞って開発し、基本機能の有用性および将来的な他申請（指導受け等）への拡張性を検証する。

## 2. 目的
- 申請から承認までのリードタイム短縮。
- 休暇残数の自動計算・管理による管理コスト削減。
- ペーパーレス化の促進。

## 3. スコープ
- **対象**: 休暇申請の登録、承認・差戻しフロー、残数管理、一覧閲覧、印刷（PDF）、ダッシュボード。
- **対象外**: Active Directory連携、実際のメール送信（モックで代替）、他システムとの自動データ同期。

## 4. 用語定義
- **申請者**: 休暇申請を起票するユーザー。
- **承認者**: 申請内容を確認し、承認・差戻しを行う権限を持つユーザー。
- **管理者**: システム全体の設定や全申請データの閲覧権限を持つユーザー。
- **決裁**: ワークフローの最終段階の承認のこと。

## 5. 機能一覧
1. **休暇申請機能**: 新規申請、一時保存(下書き)、申請内容の閲覧。
2. **ワークフロー機能**: 承認、差戻し、取消、承認ルートの自動適用。
3. **休暇残数管理機能**: 月次付与、年次繰越、申請に伴う残数引き落とし。
4. **承認ルート設定機能**: 申請者ごとのデフォルト承認ルートの管理。
5. **通知機能**: イベント発生時の通知（モック実装）。
6. **閲覧・権限管理**: ユーザーのロールに応じたデータアクセス制御。
7. **ダッシュボード**: 休暇取得状況のグラフ表示・サマリ表示。
8. **印刷機能**: 承認完了データのブラウザベースでのPDF出力。

## 6. 非機能要件整理
- **パフォーマンス**: 通常操作3秒以内、一覧取得5秒以内のレスポンス。
- **セキュリティ**: JWT認証、ロールベースアクセス制御(RBAC)。操作ログの記録。
- **可用性**: 業務時間内（平日9:00〜18:00）稼働を想定した設計。

## 7. 全体構成図
(テキスト表現)
[Client (Browser)] <--(HTTP/REST)--> [Next.js (Frontend)] <--(HTTP/REST)--> [ASP.NET Core (Backend API)] <--(EF Core)--> [Database]

## 8. 技術選定理由
- **Next.js**: 高速なレンダリングとモダンなUIコンポーネント(React)の活用。
- **ASP.NET Core Web API**: 堅牢なバックエンド構築、クリーンアーキテクチャの容易な実装。
- **EF Core (In-Memory/MySQL)**: 開発スピードの向上および将来的なRDBへのシームレスな移行。

## 9. コンポーネント構成
- **UI層**: ページコンポーネント、UIパーツ、カスタムフック。
- **API層**: Controllers, Middleware, JWT認証処理。
- **Application層**: ユースケース実装 (RequestService, WorkflowService など)。
- **Domain層**: エンティティモデル、リポジトリインターフェース。
- **Infrastructure層**: DBコンテキスト実装、モック通知サービス実装。

## 10. 外部依存
- **なし**: PoC段階では外部システムへの依存は最小限（DBのみ）とする。

## 11. 制約事項
- 開発期間の都合上、PoCでは通知機能はコンソール出力またはログ記録とする。
- PDF出力はフロントエンドのブラウザ標準機能を基本とする。
