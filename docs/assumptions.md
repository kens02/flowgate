# 補完仕様・前提条件 (Assumptions)

要件定義書の記載内容から、設計・実装を進めるにあたり不足している仕様を以下の通り補完・仮定する。

## 1. ユーザー管理・認証
- **ユーザー情報**: PoC段階ではActive Directory連携などの外部IDプロバイダ連携は行わず、モックのユーザーデータ（またはDB上のユーザーテーブル）を使用し、ログインフォームで選択・または固定のユーザーIDでログインするものとする。
- **ロール**: `Applicant` (申請者), `Approver` (承認者), `Admin` (管理者) の3ロールとし、ユーザーは複数のロールを兼務可能とする。
- **認証方式**: JWTベースのBearer認証を実装する。

## 2. 休暇申請の仕様詳細
- **休暇種別**: 「年次有給休暇」「特別休暇（慶弔など）」「代休」の3種を基本マスタとして想定する。
- **時間単位の制限**: 同日に重複する時間帯の申請は不可とする。
- **添付ファイル**: PoCではファイルアップロード機能をモック（S3やAzure BlobではなくローカルストレージまたはDBのバイナリ保存、もしくは機能としてUIのみでバックエンドはスキップ）とするが、今回はAPIとしては受け付ける形（ローカル保存）を想定する。

## 3. ワークフロー詳細
- **承認ルート**: 申請時に自動的にユーザーに紐づいたデフォルト承認ルート（最小4名）がセットされるものとする。
- **差戻し（Rejected）後の再申請**: 差戻しされた申請は申請者が修正し、再度初めから承認フローをやり直すものとする。
- **取消（Cancelled）**: 申請中（Submitted）または承認中（InReview）のステータスの場合のみ取消可能とする。承認済（Approved）の取消は別途「取消申請」が必要となる可能性があるが、PoCでは考慮しない。

## 4. UI/UX
- **画面構成**: 
  - ログイン画面
  - ダッシュボード画面
  - 申請一覧・検索画面
  - 申請詳細・承認画面
  - 承認ルート設定画面
- **言語**: 日本語のみとする。
- **デザイン**: Next.js (App Router) + Tailwind CSS + shadcn/ui などを利用し、モダンなUIを構築する。

## 5. バックエンド・DB
- **技術スタック**: ASP.NET Core 8.0 Web API を想定する。
- **ORM**: Entity Framework Core を使用し、最初はInMemory Providerで動作可能とする。
- **CORS**: Next.js からのアクセスを許可するよう設定する。

## 6. 通知機能
- **実装方式**: PoCでは実際のメール送信は行わず、ログ出力またはモックのメール送信サービス（Mailhog等、あるいは単にコンソール出力）で代替する。

## 7. 印刷機能
- **実装方式**: ブラウザの標準印刷機能（CSSによる印刷用スタイル調整）を活用するか、Puppeteer/jsPDF等を用いたフロントエンドでのPDF生成を想定する。バックエンドでのPDF生成は行わない。
