# テスト仕様書

## 1. テスト戦略
PoCフェーズであるため、テスト工数と品質のバランスを考慮し、以下の方針とする。
- **バックエンド**: 複雑なビジネスロジック（休暇日数計算、ワークフロー状態遷移）を持つドメイン層およびアプリケーション層を中心に単体テスト（ユニットテスト）を実施。
- **フロントエンド**: 主要なコンポーネントのレンダリングテスト、およびユースケースに沿ったE2E(End-to-End)テストを最小限実施。

## 2. 単体テスト観点 (Backend)
- **LeaveCalculationService**
  - 時間休（15分単位）の正しい減算計算。
  - 日休（7時間45分）の正しい減算計算。
  - 残数不足時のエラー送出。
- **WorkflowService**
  - 承認時の次のステップへの正常な遷移（InReview の維持 または Approved への移行）。
  - 最終承認時の Request ステータスの Approved への移行。
  - 差戻し時の Request および 全 WorkflowStep の Rejected への移行。

## 3. 結合テスト観点 (API)
- `POST /api/requests` による一連のデータ登録（Request, WorkflowStep, ActionHistory）が正しく行われること。
- トランザクション処理により、DBの一部更新のみで失敗（コミットされない）ケースがないことの確認。

## 4. 境界値テスト
- 休暇時間の最小単位（15分）。
- 日をまたぐ申請（今回は非対応とし、エラーになること）。
- 休暇残数が0日の場合の申請。
- 休暇残数がピッタリ残っている場合の申請。

## 5. 異常系テスト
- 存在しない Request ID に対する承認操作（404 Not Found）。
- 自分の承認順序ではないステップでの承認操作（403 Forbidden または 400 Bad Request）。
- 既に完了（Approved または Cancelled）した Request に対する操作。

## 6. 負荷テスト方針
PoCフェーズのため、特別な負荷テストツール（JMeter等）を用いた大規模な負荷テストは実施しないが、数十件の同時リクエストに対するインメモリDBの挙動は手動またはスクリプトで簡易確認する。
